1. Core Java Deep Dive

Core Java • OOP Principles
Q1: Explain the 4 fundamental Pillars of Object-Oriented Programming (OOP).
1. Encapsulation: Wrapping data (fields) and methods operating on data into a single unit (class), restricting direct access using private access modifiers with public getters and setters (e.g., User.java).
2. Inheritance: Mechanism where a child class acquires properties and behaviors of a parent class using extends (e.g., ProductServlet extends HttpServlet).
3. Polymorphism: Ability of an object to take many forms.
  • Compile-time (Method Overloading): Same method name with different parameter signatures.
  • Runtime (Method Overriding): Child class overriding a method defined in the parent class (e.g., overriding doGet() in Servlets).
4. Abstraction: Hiding internal implementation details and exposing only essential functionality using abstract classes or interfaces (e.g., ProductDAO interface).

Core Java • Collections Framework
Q3: Differentiate ArrayList vs LinkedList, and explain how HashMap works internally.
- ArrayList vs LinkedList:
  • ArrayList: Backed by a dynamic array. Fast random access O(1), slow insertions/deletions O(N) due to element shifting. Used in ProductDAOImpl.java to store product lists.
  • LinkedList: Backed by a doubly linked list. Fast insertions/deletions O(1), slow element access O(N).
- HashMap Internal Working: HashMap stores data as Key-Value pairs in an array of Buckets (Nodes). 1. When calling map.put(key, value), Java calculates hashCode(key) to determine bucket index. 2. If multiple keys hash to the same bucket index (**Collision**), elements are stored in a LinkedList (or Red-Black Tree in Java 8+ if chain length > 8). 3. equals() method is used during map.get(key) to locate the exact node.
Core Java • Exception Handling
Q4: Explain Exception Handling: Checked vs Unchecked exceptions and try-catch-finally.
- Checked Exceptions: Checked at compile-time (e.g., SQLException, ClassNotFoundException in JDBC). Must be caught or declared using throws.
- Unchecked Exceptions: Occur at runtime extending RuntimeException (e.g., NullPointerException, NumberFormatException).
- try-catch-finally / try-with-resources: try block contains risky code. catch block handles specific exceptions. finally executes regardless of exceptions (used for closing resources). StyleSphere uses try-with-resources to close JDBC connections automatically.
Core Java • Strings & Memory
Q5: Explain String immutability vs StringBuilder vs StringBuffer and String Constant Pool.
- String: Immutable object. Any modification creates a new String instance in the String Constant Pool (SCP) within heap memory.
- StringBuilder: Mutable string buffer. Fast and non-synchronized (not thread-safe). Used in ProductDAOImpl.java to construct dynamic SQL queries efficiently.
- StringBuffer: Mutable and synchronized (thread-safe, slower).
Core Java • JVM Architecture
Q6: What is the difference between JDK, JRE, and JVM? Explain JVM Memory Architecture.
- JDK (Java Development Kit): Full development kit containing JRE + compiler (`javac`) + development tools.
- JRE (Java Runtime Environment): Runtime environment containing JVM + core class libraries needed to execute Java apps.
- JVM (Java Virtual Machine): Virtual machine that executes Java bytecode (`.class`).
- JVM Memory Structure: 1. Heap Memory: Stores all instantiated objects (e.g., `Product` instances). 2. Stack Memory: Stores local variables and method execution call frames. 3. Method Area / Metaspace: Stores class structures, constant pools, and static variables. 4. JIT Compiler: Compiles bytecode to native machine code at runtime for optimization. 5. Garbage Collector (GC): Automatically reclaims heap memory allocated to unreferenced objects.

JDBC • Transactions & Batch Processing
Q8: How do Transactions, Commit, Rollback, and Batch Processing work in JDBC?
- Transaction Management: By default, JDBC auto-commits after every SQL statement (`conn.setAutoCommit(true)`). To group multiple SQL queries (e.g., inserting into `orders` AND `order_items` atomically): 
conn.setAutoCommit(false);
try {
    // 1. Insert order
    // 2. Insert order_items
    conn.commit(); // Save transaction
} catch(Exception e) {
    conn.rollback(); // Undo transaction on error
}
- Batch Processing: Allows grouping multiple SQL statements and sending them to the database in a single network round-trip using ps.addBatch() and ps.executeBatch(), dramatically improving bulk insert speed.

Servlets • Config, Context, Filters, Listeners
Q10: Explain ServletConfig vs ServletContext, Filters, and Listeners.
- ServletConfig: One per Servlet instance. Used to pass initialization parameters specific to that single servlet.
- ServletContext: One per Web Application. Shared across all servlets in the app to store global parameters.
- Servlet Filters (`CorsFilter.java`): Intercepts requests/responses before reaching servlets or returning to client. Used for CORS, authentication checks, and logging.
- Listeners: Monitors events in servlet context or sessions (e.g., HttpSessionListener tracking active online users).

5. Database & SQL Deep Dive

Database • Keys, Normalization & Joins
Q12: Explain Primary, Foreign, Unique, and Composite Keys, Normalization, and Joins.
- Keys:
  • Primary Key: Uniquely identifies each record (e.g., product_id). Cannot be NULL.
  • Foreign Key: References Primary Key of another table establishing relationships (e.g., category_id in products).
  • Unique Key: Enforces unique values but allows a single NULL value (e.g., email in users).
  • Composite Key: Combination of two or more columns forming a unique key (e.g., (category_id, subcategory_name)).
- Normalization: Organizing schema to reduce data redundancy. 1NF (atomic columns) -> 2NF (remove partial dependencies) -> 3NF (remove transitive dependencies). - Joins: `INNER JOIN` (matches in both tables), `LEFT JOIN` (all rows from left table + matched right rows, used in `ProductDAOImpl`), `RIGHT JOIN`, `FULL OUTER JOIN`.
Database • Aggregates, GROUP BY, HAVING, Stored Procedures
Q13: Explain Aggregate Functions, GROUP BY vs HAVING, Views, and Stored Procedures.
- Aggregate Functions: COUNT(), SUM(), AVG(), MIN(), MAX().
- GROUP BY vs HAVING: WHERE filters rows *before* aggregation. GROUP BY groups rows. HAVING filters aggregated groups *after* GROUP BY.
- Views: Virtual table based on the result-set of an SQL statement.
- Stored Procedures & Triggers: Stored Procedures are pre-compiled SQL scripts stored in database executed via CallableStatement. Triggers are automated SQL blocks executed before/after INSERT/UPDATE/DELETE events.
